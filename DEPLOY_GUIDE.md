# DaniDunner — деплой на Vercel + Supabase (домейн cfxwebstudio.xyz)

## 1. Създаване на базата данни в Supabase

1. Отидете на https://supabase.com → New Project.
2. Изберете регион близо до Европа (напр. Frankfurt).
3. След като проектът се създаде: **Project Settings → Database → Connection string → URI**.
4. Копирайте connection string-а (изглежда така: `postgresql://postgres:[PASSWORD]@[HOST]:5432/postgres` или pooled вариант през порт 6543 — препоръчително е pooled вариантът за serverless/Vercel, с `?pgbouncer=true` в края).
5. Това е стойността за `DATABASE_URL`.

Схемата (таблиците) се създава автоматично при първо стартиране на сайта — няма нужда да пускате ръчно SQL скрипт.

## 2. Deploy във Vercel

1. Качете кода в GitHub repo (ако вече не е там).
2. Отидете на https://vercel.com → New Project → изберете repo-то.
3. В **Environment Variables** добавете:
   - `DATABASE_URL` = connection string-ът от Supabase (стъпка 1)
   - `SESSION_SECRET` = дълъг случаен низ (напр. генерирайте с `openssl rand -hex 32`)
   - `STRIPE_WEBHOOK_SECRET` = вижте отделната секция **"Stripe — картови плащания"** по-долу; може да се добави и по-късно, без да пречи на останалата част от сайта.
4. Deploy.
5. В **Project Settings → Domains** добавете `cfxwebstudio.xyz` и посочете DNS записите на регистратора на домейна както Vercel показва (обикновено A запис към Vercel IP или CNAME).

## 3. Настройки в самия сайт (Настройки в админ панела)

След първия deploy отворете `https://cfxwebstudio.xyz/admin` (или през нормален вход, виж т.5) и в **Настройки** проверете/попълнете:

- `site_domain` — вече е предварително зададено на `cfxwebstudio.xyz`.
- `admin_email` — имейлът, с който Вие ще влизате (виж т.5).
- `stripe_publishable_key` / `stripe_secret_key` — вижте **"Stripe — картови плащания"** по-долу.
- `resend_api_key` / `notification_from_email` — вижте **"Resend — имейл потвърждения"** по-долу.
- `google_client_id` / `google_client_secret` — ако ползвате "Вход с Google" (виж т.6).

## 4. Демо съдържание

Прясната база е празна освен предварително заредената категория „Напитки" и зоните за доставка във Варна. Продукти (пици, дюнери, бургери и т.н.), промо кодове и куриери се добавят през админ панела — Продукти / Промоции / Куриери.

## 5. Как влиза администраторът

Влизате като всеки нормален клиент — през обичайната форма за регистрация/вход на сайта (имейл + парола, или Google). Когато имейлът съвпада с `admin_email`, зададен в Настройки, автоматично получавате и админ достъп (виждате линк към админ панела). Старата отделна форма `/admin/login` (с админския акаунт от `admin_users` таблицата) продължава да работи като резервен вариант, но не е нужна за ежедневна употреба.

## 6. Как влизат куриерите

Точно както преди — през **Куриери** в админ панела създавате куриер с телефон и парола, зададени от Вас. Куриерът влиза през `/courier/login` с тези данни. Няма нужда от отделна регистрация — само Вие раздавате достъп.

## 7. Google Login — смяна на адреса за новия домейн

За да проработи "Вход с Google" на `cfxwebstudio.xyz`:

1. Отидете на **Google Cloud Console** → https://console.cloud.google.com
2. Изберете проекта, в който е създаден OAuth клиентът за сайта.
3. **APIs & Services → Credentials**.
4. Отворете съществуващия **OAuth 2.0 Client ID** (този, който вече ползвате).
5. В **Authorized JavaScript origins** добавете:
   `https://cfxwebstudio.xyz`
6. В **Authorized redirect URIs** добавете:
   `https://cfxwebstudio.xyz/api/account/google/callback`
7. Запазете. Промяната отнема няколко минути да влезе в сила.

(Старите localhost адреси можете да оставите или изтриете — не пречат.)

## 8. Stripe — картови плащания

Ключовете се въвеждат в самия сайт (**Настройки → "Разплащане с карта онлайн"**), не в Vercel — с едно изключение (webhook secret, стъпка 4 по-долу), което е в Vercel, защото се чете директно от кода, не от базата.

1. Създайте акаунт на https://dashboard.stripe.com (или ползвайте съществуващ).
2. **Developers → API keys**. Копирайте:
   - **Publishable key** (`pk_...`)
   - **Secret key** (`sk_...`) — пазете го, не го споделяйте.
   Докато тествате, ползвайте ключовете в **Test mode** (превключвателят горе вдясно в Stripe таблото) — плащанията с тестова карта `4242 4242 4242 4242` (произволна бъдеща дата, произволен CVC) минават без реални пари. Когато сте готови за истински плащания, превключете на **Live mode** и вземете живите ключове оттам.
3. В сайта: **Настройки → "Разплащане с карта онлайн (Stripe)"** → въведете двата ключа → **Запази настройките**. Активира се веднага, без redeploy.
4. **Webhook** (нужен е, за да разбира сайтът кога плащането е минало успешно):
   - В Stripe: **Developers → Webhooks → Add endpoint**.
   - Endpoint URL: `https://cfxwebstudio.xyz/api/webhooks/stripe`
   - Events to send: изберете `checkout.session.completed`.
   - След създаване отворете новия endpoint → **Signing secret** → копирайте стойността (започва с `whsec_...`).
   - Във Vercel: **Project Settings → Environment Variables** → добавете `STRIPE_WEBHOOK_SECRET` = тази стойност → **Redeploy** (само тази стъпка изисква redeploy, защото е environment variable, не настройка в базата).
5. Тествайте с реална поръчка (в Test mode с картата по-горе) — статусът на поръчката в админ панела трябва да стане автоматично "платена" секунди след плащането.

### (По желание) Автоматично разделяне на плащането за пица

Ако искате делът от плащането за пица-продукти автоматично да отива в друга Ваша Stripe сметка (напр. ако пицарията и дюнерджийницата се водят като отделни бизнеси):

1. Създайте втори Stripe акаунт за пицарията (или ползвайте съществуващ) и активирайте го за **Stripe Connect** (по подразбиране всеки Stripe акаунт може да получава transfers като "connected account" на друг акаунт — вижте Stripe документацията "Connect" при първо ползване, Stripe Ви превежда през нужните стъпки/верификация).
2. Копирайте неговото Account ID (изглежда като `acct_xxxxxxxxxxxxxxxx`, вижда се в **Settings → Account** на съответния акаунт).
3. В сайта: **Настройки → "Автоматично разпределяне на плащанията"** → въведете това ID.
4. Оставете полето празно, ако не искате тази функция — всичко остава в основната сметка, както е по подразбиране.

## 9. Resend — имейл потвърждения на поръчка

По желание — ако не го настроите, чекаутът работи по същия начин, просто клиентът не получава имейл с потвърждение.

1. Създайте акаунт на https://resend.com.
2. **Domains → Add Domain** → въведете Вашия домейн (напр. `cfxwebstudio.xyz` или под-домейн като `mail.cfxwebstudio.xyz`) → Resend ще покаже няколко DNS записа (SPF, DKIM, понякога DMARC) → добавете ги при регистратора на домейна (същото място, откъдето сте сочили домейна към Vercel) → изчакайте статусът в Resend да стане "Verified" (обикновено от минути до няколко часа, зависи от DNS пропагацията).
3. **API Keys → Create API Key** → копирайте стойността (показва се само веднъж).
4. В сайта: **Настройки → "Имейл потвърждение на поръчка (Resend)"**:
   - **Resend API key** — стойността от стъпка 3.
   - **Адрес "От"** — трябва да е на верифицирания домейн от стъпка 2, напр. `DannyFoods <поръчки@cfxwebstudio.xyz>`. Ако адресът е на друг, неверифициран домейн, изпращането ще се провали тихо (поръчката се създава нормално, просто без имейл — вижте логовете във Vercel ако искате да проверите причината).
5. Запази настройките — активира се веднага, без redeploy.
6. Тествайте с поръчка, в която сте въвели свой имейл — потвърждението трябва да пристигне до секунди.

## Технически бележки (за архивна информация)

- Базата данни премина от локален SQLite файл (`node:sqlite`) към Postgres чрез `pg` — необходимо, защото Vercel е serverless и няма постоянен локален диск между заявките.
- Целият достъп до базата вече е асинхронен (`await`) — типизирано е и проверено с `tsc --noEmit` и `eslint` без грешки.
- Тествано е пълно с реална Postgres база: начална страница, регистрация/вход (вкл. автоматично разпознаване на админ имейл), пълна поръчка (checkout), админ панел (продукти/зони/промоции/куриери/настройки), пълния куриерски флоу (вход, вземане на поръчка, живо местоположение, статус "доставя"/"доставено").
- `npm run build` (production build) не можа да се тества докрай в sandbox средата само защото няма изходящ достъп до fonts.googleapis.com оттук (next/font сваля Google Fonts по време на build) — на Vercel това ще проработи нормално, тъй като техните build сървъри имат пълен интернет достъп.
